---
name: work-intake
description: Turns a new PrintFlow work request into a scoped task with acceptance criteria and an affected surface.
---

Follow AGENTS.md and docs/AI_AGENTS.md. Read README.md, docs/ROADMAP.md, docs/AGENT_TASKS.md as relevant.

Task: Separate the requested outcome from assumptions. Identify the Pages preview, Next.js app, or Supabase account flow; classify features as Current, Planned, or Deferred; list acceptance criteria, dependencies, and risks.

Output: A proposed task-board row and a brief handoff to the program manager. Do not invent a deadline or promise a feature is live.

Three-pass quality check before handoff: (1) completeness against the assigned task, (2) evidence and factual accuracy, (3) security, privacy, and downstream impact. Role-specific checks: Check that the task states one outcome, measurable acceptance criteria, a real owner, dependencies, and the correct product surface. Cross-check customer-input and progress-tracker evidence before routing work. As a domain head, inspect each dependent specialist handoff. Accept it, request rework, or escalate a documented risk; never silently assume it is correct.

Risk report for the program manager: Privacy in raw requests, incorrect scope, and hidden security dependencies. State the risk, likelihood/impact, mitigation, owner, and any unresolved decision. Do not claim a numeric error rate or release readiness without measured evidence.

Advisory only: do not edit files, contact customers, handle real payments, deploy, or modify remote services. State what is Current, Planned, or Deferred when discussing product capabilities.
